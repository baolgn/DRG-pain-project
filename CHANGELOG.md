# Changelog

## 2026-11-09

[drg5_acquisition_records.sv](microcontroller/rtl/drg5_acquisition_records.sv) adds an ordered reservation ledger for synthetic complete records. It reserves a physical entry before admitting a slot and keeps that entry charged through conversion, placeholder construction, assembly, FIFO waiting and DMA staging. Only release of an unused reservation or a matching positive DMA completion returns capacity. The default ring contains 256 entries of 56 bytes each, holding the 48-byte record and its slot index. A later placeholder can finish assembly before an older conversion, but the older slot must leave the ring first. Cancellation of an unresolved synthetic conversion retains a triggered missing record; cancellation cannot alter a record already offered to DMA.

[drg5_acquisition_storage.sv](microcontroller/rtl/drg5_acquisition_storage.sv) connects the scheduler's launch and notification interfaces to those reservations. It preallocates the first entry before ARM, consumes that reservation on the launch edge and treats the later triggered notification as confirmation of the existing owner. An untriggered notification consumes the same reserved capacity for a missing-slot record. The adapter waits for outstanding notifications before releasing an unused spare at stop, reports all occupied stages to the scheduler and retains protocol faults independently of CPU service. The [reservation contract](microcontroller/acquisition/record-reservations.md) and [integration specification](microcontroller/acquisition/storage-integration.md) define identities, simultaneous-operation precedence, complete-record transfers, fault reporting and reset obligations. This path uses one clock; asynchronous FIFO pointers, coordinated clock-domain reset, serial capture, actual DMA memory writes and CPU board integration remain unimplemented in this path.

The test wrappers [run_acquisition_records.py](microcontroller/tests/run_acquisition_records.py) and [run_acquisition_storage.py](microcontroller/tests/run_acquisition_storage.py) execute the stimulus and comparisons in [drg5_acquisition_records_tb.sv](microcontroller/tests/drg5_acquisition_records_tb.sv) and [drg5_acquisition_storage_tb.sv](microcontroller/tests/drg5_acquisition_storage_tb.sv). The [retained results](microcontroller/acquisition/evidence/records-2026-11-09/README.md) pass 26 ledger cases and 160 randomized records under each of three deterministic Verilator seeds, with Icarus repeats at depths four and 256. Seven connected scheduler/storage cases pass in both simulators, including a full-buffer slot deadline coinciding with positive DMA completion: the retirement does not supply admission credit for that same edge. Other cases check stable stalled payloads, cancellation races, ordered placeholders, simultaneous transfers and token exhaustion. Seven deliberately corrupted observations fail their intended comparisons. Yosys retains the two default-depth memories and finds no latches during structural checks; full generic synthesis passes at depth four. These tests use synthetic capture and DMA peers and do not establish physical recording, asynchronous FIFO correctness, routed timing or board programming.

## 2026-11-06

[drg5_acquisition_control.sv](microcontroller/rtl/drg5_acquisition_control.sv) adds a separate acquisition control peripheral with unqualified, startup, configuration, ready, running, closing, stopped and fault states. A command register write returns an admission result without waiting for startup or configuration to finish. Accepted ordinary commands retain a separate final result until software acknowledges its identity. Shadow writes remain separate from the captured candidate and active configuration, and a frozen status bank allows RV32 software to read counters and evidence without mixing different clock edges. The [component interface](microcontroller/acquisition/control-foundation.md) defines register offsets, command precedence, backend obligations and reset behavior.

The peripheral preserves first and latest fault evidence, sticky causes, event sequence and loss counts outside its event queue. CPU reset requests a hardware stop or service cancellation while retaining peripheral state. A full event queue preserves its older entry, records the dropped occurrence and inhibits recording without waiting for software. Configuration, cancellation and closure have bounded waits. The component uses explicit synchronous qualification, service and closure inputs; it does not implement the ADC sequencer, recording DMA, independent clock supervisor or domain crossings, and the current CPU fabric does not instantiate it.

[drg5_acquisition_timebase.sv](microcontroller/rtl/drg5_acquisition_timebase.sv) supplies a free-running 64-bit acquisition counter that survives CPU reset and saturates before wrap. [drg5_acquisition_scheduler.sv](microcontroller/rtl/drg5_acquisition_scheduler.sv) keeps a separate 64-bit slot count and accepts a binding whose first slot is due one tick after ARM acceptance. Every subsequent slot remains 1,600 acquisition ticks apart. On each due edge, the scheduler either raises the CONVST register or ends the epoch. When it suppresses a due conversion, it retains an explicit missing-slot decision if capacity permits; otherwise, it records the lost slot in the end receipt. It never issues a delayed conversion with an earlier timestamp. Ordinary stop finishes an emitted eight-tick pulse, while isolation can invalidate it. If a scheduling notification is not accepted by its inclusive 80-tick deadline, the scheduler stops without CPU service and seals an uncertain end receipt while keeping the original tuple owned.

[drg5_acquisition_timing.sv](microcontroller/rtl/drg5_acquisition_timing.sv) connects the controller and scheduler to the same counter. ARM commits both components on the command acceptance edge; the registered ARM observation cannot introduce another cycle of delay. Closure requires a matching scheduler receipt and retirement of local owners. A separate acknowledgment releases that receipt only after the controller seals the same epoch. Scheduler fault occurrences use a counted input, so adjacent reports remain observable when the event queue is full. The [integration contract](microcontroller/acquisition/timing-integration.md) defines these ownership rules. The [scheduler specification](microcontroller/acquisition/slot-scheduler.md) identifies the timestamp with the FPGA edge driving CONVST and allocates a candidate 2.75 ns path to the ADC pin. That physical offset is unmeasured, and routed timing, ADC capture, record assembly and CPU board integration remain outstanding.

The test wrappers [run_acquisition_scheduler.py](microcontroller/tests/run_acquisition_scheduler.py) and [run_acquisition_timing.py](microcontroller/tests/run_acquisition_timing.py) build and run [drg5_acquisition_scheduler_tb.sv](microcontroller/tests/drg5_acquisition_scheduler_tb.sv) and [drg5_acquisition_timing_tb.sv](microcontroller/tests/drg5_acquisition_timing_tb.sv), which implement the stimulus and comparisons. The [retained campaign](microcontroller/acquisition/evidence/scheduler-2026-11-06/README.md) passes 30 scheduler cases under three deterministic Verilator seeds and ten connected-interface cases, then repeats both suites with four-state Icarus simulation. The connected cases apply MMIO response backpressure for more than 5,000 clocks while checking unchanged slot spacing and exercise downstream stalls, stop ordering and premature acknowledgments. They model CPU requests without executing the CPU core. The control test wrapper [run_acquisition_control.py](microcontroller/tests/run_acquisition_control.py) also runs the stimulus and comparisons in [drg5_acquisition_control_tb.sv](microcontroller/tests/drg5_acquisition_control_tb.sv), passing 53 named cases per seed, including adjacent fault occurrences and all 24 lifecycle and ordinary-command combinations. Reduced-counter cases exercise exhaustion, twelve deliberately corrupted observations fail their intended comparisons, and Yosys completes generic synthesis without inferred latches. These runs use modeled backends and reduced service timeouts. They establish the exercised simulation behavior and generic synthesis results, while routed 80 MHz timing, physical acquisition and board programming remain untested by these campaigns.

## 2026-11-05

The [clock/reset lifecycle specification](microcontroller/acquisition/clock-reset-lifecycle.md) adds ACQ-R1-CDC1 to the revision-4 acquisition contract without changing the binary formats. It defines a fixed acquisition clock with clock enables, coherent command and status crossings, complete-record FIFO transfers, and separate CPU, acquisition, system and FPGA-reconfiguration reset scopes. CPU-only reset must retain peripheral requests and ownership while stopping acquisition; reset that erases timing or accounting requires containment and a new recording session. These are implementation requirements, with physical clock-domain-crossing and reset qualification still open. The `explore()` function in [check_lifecycle.py](microcontroller/acquisition/check_lifecycle.py) checks finite abstract models rather than the complete RTL, including delayed stop observation, FIFO isolation and epoch-metadata delivery. The retained run exhausted 1,684 states and 7,053 transitions across five models, reached 38 coverage targets and detected all nine deliberately unsafe variants.

The [binary format specification](microcontroller/acquisition/formats.md) assigns byte offsets, little-endian encoding, reserved values, validity flags and integrity coverage for 48-byte records, 64-byte block headers and 64-byte publication descriptors, together with configuration, epoch and loss metadata. Recording epochs, stream block sequences and allocation generations have separate lifetimes. Partial blocks carry their actual record count, counters cannot wrap, and exact loss intervals remain distinct from uncertain availability. The host-side functions `make_record()` and `make_block()` in [format_producer.py](microcontroller/acquisition/format_producer.py) construct the encoded bytes. [format_parser.py](microcontroller/acquisition/format_parser.py) independently decodes them through `parse_record()` and `parse_block()`; `StreamLedger.accept()` and `validate_loss_intervals()` check identities, ordering and accounting across objects. [check_formats.py](microcontroller/acquisition/check_formats.py) compares the implementations against golden bytes and malformed inputs. Its final retained run passed 1,549 checks without exercising ADC capture, DMA or concurrent memory publication. The [memory allocation plan](microcontroller/memory/README.md) now includes a separate 4 KiB descriptor table and charges retirement stores to allocation-control service.

The [timing budget](microcontroller/acquisition/timing-budget.md) separates ADC limits from controller allocations while routed interface timing and physical capture performance remain unqualified. It retains the nominal 14 microsecond completed-read deadline because the full accepted BUSY window requires 13.35 microseconds at the nominal clock before the additional conservative allowance. The proposed 13 microsecond deadline cannot cover that window. Clock tolerance, synchronization, FPGA I/O, board routing, setup and hold, storage service and independent supervision receive explicit budgets. The `calculate()` function in [check_timing.py](microcontroller/acquisition/check_timing.py) computes the margins and rejects unsupported or excessive translator delay. The retained arithmetic run checked 36,064 capture edges across 161 BUSY-fall positions, a conservative enumeration that does not admit unmatched BUSY sequences.

The [evaluation-board interface review](microcontroller/acquisition/board-qualification.md) traces signal direction, ownership, power selection, reference configuration and VDRIVE from the ADC documentation and board drawings. It identifies J1 through J8 as the positive and negative inputs for channels 1 through 4, corrects the STBY and PAR/SER U4 pin assignments, and records the VIN-pulled regulator-enable path and R77 CONVST-to-CS compatibility-link restriction. The direct interface requires qualified rail tracking, sequencing and unpowered isolation as well as compatible logic levels. [board-inventory.json](microcontroller/acquisition/board-inventory.json) leaves actual markings, fitted parts and measurements unverified. No physical board was available, so assembly inspection, adapter approval and electrical measurements remain outstanding.

The tool-qualification wrapper [run.py](microcontroller/qualification/run.py) runs simulation, synthesis, routing, formal checks and waveform inspection for the selected ULX3S v3.1.7 D&M board and LFE5U-85F-6BG381C device. [smoke_core.sv](microcontroller/qualification/smoke_core.sv) implements the counter, multiplier and synchronous-memory fixture, while [smoke_tb.sv](microcontroller/qualification/smoke_tb.sv) checks 2,048 active simulation cycles. [smoke_top.sv](microcontroller/qualification/smoke_top.sv) supplies the clock and device-primitive integration used for synthesis. The final recorded Verilator, Yosys, nextpnr and bitstream-generation runs passed. The wrapper also checked the pinned openFPGALoader build's reported ULX3S and FPGA support. SymbiYosys proved and covered the counter properties in [formal.sv](microcontroller/qualification/formal.sv), and an intentionally false assertion produced a counterexample. [waveform.tcl](microcontroller/qualification/waveform.tcl) confirmed that an actual GTKWave process loaded the generated waveform and expected traces; this was host GUI inspection, not board observation.

The separate P25 build wrapper [run_programmable.py](microcontroller/synth/run_programmable.py) invokes [run_fpga.py](microcontroller/synth/run_fpga.py) to synthesize, route and pack the existing [drg5_ulx3s_programmable.sv](microcontroller/synth/fpga/drg5_ulx3s_programmable.sv) design. The fresh 25 MHz build passed its guarded routing constraint and generated a bitstream; the 80 MHz result applies only to the smaller primitive fixture. The [qualification report](microcontroller/acquisition/qualification.md) leaves physical programming, readback, power-cycle boot and ADC operation untested. [program_board.py](microcontroller/programming/program_board.py) produced a host-only SRAM programming plan without executing device commands.

The [ACQ-R1 contract](microcontroller/acquisition/contract.md) defines one supported AD7606C-18 recording configuration and requires rejection of unsupported combinations without partially applying them. It specifies fixed-grid sampling, channel order, timestamp meaning, validity, missing-conversion handling, CPU responsibilities and stop/restart outcomes. An epoch binds one configuration and timing model; relevant changes terminate it. The [ADC profile](microcontroller/acquisition/adc-profile.md) fixes the register image, startup sequence, serial edges and CRC convention. Conditioned analog voltages remain the ADC input boundary, and the undecided Abbott connection supplies no assumed recording interface. The existing [acquisition guard](microcontroller/rtl/drg5_acquisition_guard.sv) still handles synthetic slot and stop accounting rather than physical ADC control. The complete recording engine remains unimplemented and unqualified.

Component READMEs provide linked contents and retain the architecture diagrams. The [microcontroller guide](microcontroller/README.md) distinguishes the implemented CPU, local platform, firmware, programming tools and verification runners from the proposed recording and analysis system. Host instructions identify Linux as the supported development environment and leave native Windows and macOS workflows unverified.

The release acceptance wrapper [acceptance.py](microcontroller/release/acceptance.py) uses `source_inventory()` and `stage_sources()` to copy active source files and documentation into an isolated workspace before invoking the selected verification runners. ## 2026-11-03

[drg5_muldiv.sv](microcontroller/rtl/drg5_muldiv.sv) added all eight RV32M multiply, divide and remainder operations. Blocking execution in X retains the instruction identity and holds completed results until consumption, preventing obsolete operations from supplying a later instruction. The [captured unit checks](microcontroller/tests/evidence/muldiv-unit-2026-11-04/README.md) exercised mixed-sign products, division by zero, signed overflow and backpressure. [drg5_decompress.sv](microcontroller/rtl/drg5_decompress.sv) added RV32C classification, HINT handling and expansion. Integration preserved the original instruction bits and length so compressed links use PC+2 and a fault on the second parcel retains the instruction-start PC. The [decompression capture](microcontroller/tests/evidence/decompress-2026-11-04/README.md) checked all 65,536 halfword encodings, while [mixed-width execution checks](microcontroller/tests/evidence/compressed-execution-2026-11-04/README.md) covered split instructions, redirects, stalls and faults separately.

[drg5_control.sv](microcontroller/rtl/drg5_control.sv) completed conservative FENCE ordering and added configurable FENCE.I coordination with [drg5_frontend.sv](microcontroller/rtl/drg5_frontend.sv). The [fence execution capture](microcontroller/tests/evidence/fence-execution-2026-11-04/README.md) checks instruction visibility and ordering; completion by an external writer must still be established before CPU instruction synchronization.

Counter verification covered RV32 high/low accesses, rollover, inhibition, writes and actual retirement in [drg5_csr.sv](microcontroller/rtl/drg5_csr.sv). Each successfully retired compressed instruction increments `minstret` once when counting is enabled; a trapping instruction does not increment it. The [counter execution records](microcontroller/tests/evidence/counter-execution-2026-11-04/README.md) distinguish these machine counters from the unimplemented Zicntr extension.

## 2026-10-30

The CPU specification defined one little-endian, machine-mode hart and separate intermediate feature profiles. It pinned RV32I 2.1, M 2.0, C 2.0, Zicsr 2.0, Zifencei 2.0, Machine Architecture 1.13 and Debug 1.0, with explicit alignment, reset, exception, CSR and unsupported-operation behavior. The current [CPU guide](microcontroller/rtl/README.md) distinguishes configurable core features from the capabilities selected by each platform wrapper.

Platform budgets separated CPU block processing from ADC conversion timing, serial capture, timestamps and raw-data movement. The proposed 256-frame block at 50 kSPS gives a 5.12 ms interval; the initial 80 MHz target reserved 4 ms for firmware and specified memory-service, interrupt, halt, division and resource limits. These were design targets rather than measured performance. Toolchain planning selected Ubuntu/Linux and ULX3S v3.1.7 with an LFE5U-85F-6BG381C, using the open-source synthesis flow now described in the [synthesis guide](microcontroller/synth/README.md). Small-design tool checks did not establish physical programming or integrated CPU timing.

The interface contract established request ownership at first valid, with stable payload through acceptance and retained responsibility through response. Interrupt and debug arbitration precede launch; instruction metadata preserves PC, original bits, length, operands, results and faults across stalls and redirects. The simulation design specified independently delayed acceptance and completion, side-effectful MMIO counters, error responders, reproducible seeds and separate retirement and bus-effect checks. These were specification and test-environment definitions; operational CPU verification followed with the implementations described above.

# Changelog

Development dates follow the project schedule. Verification results retain the execution dates and source hashes of their captured runs, including checks performed after the corresponding development date. A historical result applies to its recorded configuration and source revision.

## 2026-11-05

The [acquisition timing budget](microcontroller/acquisition/timing-budget.md) separates ADC requirements from controller choices before state-machine design. ACQ-R1 revision 3 retains its nominal 14 µs read deadline: exact worst-case edge counting needs 13.35 µs, so the proposed 13 µs limit is rejected for the full admitted BUSY window. The budget includes clock tolerance, CDC, FPGA I/O and board/translator paths, setup/hold, service, storage and independent supervision. An offline checker verifies positive margins and rejection controls; actual capture-path timing remains unqualified. Review also corrects the swapped STBY/PAR-SER U4 pin numbers against the ADC datasheet and board schematic. No RTL or state machine is added.

The [electrical and Ubuntu qualification](microcontroller/acquisition/qualification.md) adds a schematic-level ADC board routing/ownership review, an explicitly unverified assembly inventory, and repeatable open-source tool checks for ULX3S v3.1.7 D&M / LFE5U-85F-6BG381C. The review corrects J1–J8 channel interpretation, identifies the VIN-pulled regulator-enable net and R77 compatibility-link hazard, and tightens the direct-interface voltage/rail-tracking requirements. Fresh primitive and full P25 CPU builds generate bitstreams; simulation, formal checks, actual GTKWave loading and a host-only programming plan pass. The user has no board available, so physical inspection, ADC adapter approval, electrical measurements and programming remain unperformed. New qualification code follows the existing comment conventions; historical evidence stays bound to its original inputs.

The [ACQ-R1 acquisition contract](microcontroller/acquisition/contract.md) now defines one supported ADC configuration, atomic rejection of unsupported combinations, fixed-grid sampling, channel order, timestamp and record validity, configuration epochs, missing conversions, CPU duties, and exact or uncertain stop/restart outcomes. The [ADC profile](microcontroller/acquisition/adc-profile.md) fixes the register image, startup, serial edges and CRC convention. The [review](microcontroller/acquisition/review.md) records repeated corrections and independent definition checks. Thirty-seven comments were added across nine active source/build files without changing executable tokens. The complete physical acquisition engine remains unimplemented and unqualified.

The [project README](README.md) now introduces the complete DRG recording and analysis scope, with installation instructions and linked sections for the microcontroller, development documentation and hardware references. Every README includes a table of contents, and the component guides retain the architecture diagrams. Evidence checksum manifests update only the README entries affected by navigation changes; captured test data and recorded execution-source hashes remain unchanged.

The project documentation now separates the implemented CPU, local platform, firmware, programming tools, and verification runners from the proposed recording and analysis system. The [microcontroller README](microcontroller/README.md) provides implementation tables and execution flows. Host instructions distinguish the Linux development environment from unverified Windows and macOS workflows.

The release acceptance wrapper, [acceptance.py](microcontroller/release/acceptance.py), stages current source and documentation before invoking the selected verification runners. [bootstrap_tools.py](microcontroller/release/bootstrap_tools.py) requires an explicit dependency manifest. The local-fabric target in the [test Makefile](microcontroller/tests/Makefile) supplies the evidence argument required by [run_local_fabric.py](microcontroller/tests/run_local_fabric.py). These changes do not alter the RTL or establish a new hardware qualification result.

## 2026-11-04

The combined verification workflow added directed execution, randomized programs, Sail retirement comparison, ACT4 signatures and scoped formal checks. [run_verification.py](microcontroller/verification/run_verification.py) coordinates these campaigns, while [comparison.py](microcontroller/verification/execution/comparison.py) implements independent trace comparison. [drg5_pipeline_formal.sv](microcontroller/verification/formal/drg5_pipeline_formal.sv), [drg5_progress_admission_formal.sv](microcontroller/verification/formal/drg5_progress_admission_formal.sv) and [drg5_fetch_formal.sv](microcontroller/tests/drg5_fetch_formal.sv) check selected ownership, retirement and progress properties under explicit bounds and service assumptions. The [requirements ledger](microcontroller/verification/requirements.json) records five architectural-test capacity omissions and two retained comparison failures per timing seed, involving `mcause` policy and `timeh` applicability. Complete campaign inputs are not distributed, and the recorded checks do not establish whole-core formal proof or full ISA qualification.

[drg5_soc.sv](microcontroller/rtl/drg5_soc.sv) connected the CPU to the synchronous local memories and MMIO implemented in [drg5_local_fabric.sv](microcontroller/rtl/drg5_local_fabric.sv), with a timer, retained interrupts and diagnostic output. The platform provides 8 KiB of ROM, 64 KiB of instruction RAM and 32 KiB of data RAM. [start.S](microcontroller/firmware/start.S) initializes the stack, copies initialized data and clears BSS; [trap.S](microcontroller/firmware/trap.S) preserves the interrupted register context. The host wrapper [build.py](microcontroller/firmware/build.py) compiles and inspects separate I-only and IMC firmware profiles using the ILP32 ABI and the layout in [link.ld](microcontroller/firmware/link.ld). Recorded RTL simulations exercised compiled calls, arrays, arithmetic, interrupts and exception recovery without an ADC or external-memory subsystem.

FPGA integration added clock generation and reset synchronization in [drg5_ulx3s.sv](microcontroller/synth/fpga/drg5_ulx3s.sv), with buffered UART output and diagnostic events in [drg5_board_system.sv](microcontroller/rtl/drg5_board_system.sv). [run_fpga.py](microcontroller/synth/run_fpga.py) orchestrates synthesis and routing using the board constraints in [drg5_ulx3s.lpf](microcontroller/synth/fpga/drg5_ulx3s.lpf). Local-memory changes enabled block RAM inference. The integrated design failed the 80 MHz target; recorded 25 MHz routing passed a guarded 27.7778 MHz constraint. The diagnostic interrupt handler reached 845 cycles against an 800-cycle allocation. These are routing and simulation results, not physical measurements; acquisition integration, board timing and resource allocation for the complete microcontroller remain unqualified.

The programming implementation separated volatile FPGA configuration, persistent configuration storage and CPU firmware updates. [image.py](microcontroller/programming/image.py) validates and encodes application banks, while [program_board.py](microcontroller/programming/program_board.py) plans loader operations and records explicit execution and readback when requested. [drg5_spi_boot.sv](microcontroller/rtl/drg5_spi_boot.sv) validates stored firmware and [drg5_boot_soc.sv](microcontroller/rtl/drg5_boot_soc.sv) transfers execution ownership after loading instruction RAM. Normal updates preserve the golden A bank and replace B; image validation and simulated damaged-bank recovery passed their recorded checks. [run_programmable.py](microcontroller/synth/run_programmable.py) constrains the synthesis flow to the 25 MHz programmable profile, which leaves CPU debug disabled. Physical programming, power-cycle boot and recovery remain untested.

Synthetic integration added [drg5_acquisition_guard.sv](microcontroller/rtl/drg5_acquisition_guard.sv) to retain slot identities, invalid-record counts and stop reasons independently of CPU halt and reset. [run_synthetic_cpu.py](microcontroller/tests/run_synthetic_cpu.py) runs the RTL wrapper [drg5_synthetic_debug.sv](microcontroller/tests/synthetic/drg5_synthetic_debug.sv) through the C++ harness [synthetic_cpu_sim.cpp](microcontroller/tests/synthetic_cpu_sim.cpp), combining compiled firmware with modeled capture, memory, DMA and transport. The separate native model in [stress.cpp](microcontroller/synthetic/stress.cpp), compiled and checked by [run_stress.py](microcontroller/synthetic/run_stress.py), accounted for 90 million frames over 1,800 virtual seconds using an assumed firmware service time. Host-stall checks required an initial free-buffer reserve, and memory outages exercised explicit stop and fault accounting. This endurance result does not establish thirty minutes of CPU RTL execution or physical acquisition; the integer workload in [kernel.h](microcontroller/firmware/synthetic/kernel.h) remains a diagnostic calculation rather than calibrated neural signal processing.

Release tooling added isolated software acceptance, dependency installation and deterministic packaging. [acceptance.py](microcontroller/release/acceptance.py) coordinates selected child suites; [bootstrap_tools.py](microcontroller/release/bootstrap_tools.py) checks supplied dependency identities; [package_release.py](microcontroller/release/package_release.py) builds archives and verifies their inventory, permissions and hashes. The package covers the microcontroller and documentation trees, while the complete dependency manifest is not distributed. Archive integrity and successful software checks remain separate from the unresolved architectural comparisons, timing limits and physical qualification.

## 2026-11-03

[drg5_muldiv.sv](microcontroller/rtl/drg5_muldiv.sv) added all eight RV32M multiply, divide and remainder operations. Blocking execution in X retains the instruction identity and holds completed results until consumption, preventing obsolete operations from supplying a later instruction. The [captured unit checks](microcontroller/tests/evidence/muldiv-unit-2026-11-04/README.md) exercised mixed-sign products, division by zero, signed overflow and backpressure. Multiply and divide first assert result-valid two and 33 clocks after acceptance, respectively; downstream waiting adds to those arithmetic latencies.

[drg5_decompress.sv](microcontroller/rtl/drg5_decompress.sv) added RV32C classification, HINT handling and expansion. Integration preserved the original instruction bits and length so compressed links use PC+2 and a fault on the second parcel retains the instruction-start PC. The [decompression capture](microcontroller/tests/evidence/decompress-2026-11-04/README.md) checked all 65,536 halfword encodings, while [mixed-width execution checks](microcontroller/tests/evidence/compressed-execution-2026-11-04/README.md) covered split instructions, redirects, stalls and faults separately.

[drg5_control.sv](microcontroller/rtl/drg5_control.sv) completed conservative FENCE ordering and added configurable FENCE.I coordination with [drg5_frontend.sv](microcontroller/rtl/drg5_frontend.sv). Instruction synchronization waits for older data effects, invalidates buffered instructions and drains obsolete fetch responses without losing their owners. The [fence execution capture](microcontroller/tests/evidence/fence-execution-2026-11-04/README.md) checks instruction visibility and ordering; completion by an external writer must still be established before CPU instruction synchronization.

Counter verification covered RV32 high/low accesses, rollover, inhibition, writes and actual retirement in [drg5_csr.sv](microcontroller/rtl/drg5_csr.sv). Each successfully retired compressed instruction increments `minstret` once when counting is enabled; a trapping instruction does not increment it. [drg5_observe.sv](microcontroller/rtl/drg5_observe.sv) added edge-aligned execution records, sequence and epoch identifiers, sticky overflow flags and capture invalidation for independent replay. The [counter execution records](microcontroller/tests/evidence/counter-execution-2026-11-04/README.md) distinguish these machine counters from the unimplemented Zicntr extension.

The debug implementation added halt, resume, reset-halt, abstract register access and single-instruction execution through [drg5_debug_module.sv](microcontroller/rtl/drg5_debug_module.sv), [drg5_debug_transport.sv](microcontroller/rtl/drg5_debug_transport.sv) and [drg5_debug_system.sv](microcontroller/rtl/drg5_debug_system.sv). Halt drains launched work, and resume does not repeat MMIO effects. The [wrapper simulations](microcontroller/tests/evidence/debug-system-2026-11-04/README.md) exercised public JTAG access, guarded memory operations and reset ownership. Recorded OpenOCD/GDB interoperability used the simulated transport driven by [run_debug_remote.py](microcontroller/tests/run_debug_remote.py); physical probe behavior and an assigned JTAG identity remain unqualified.

## 2026-11-02

[drg5_csr.sv](microcontroller/rtl/drg5_csr.sv) and its integration in [drg5_control.sv](microcontroller/rtl/drg5_control.sv) completed machine CSR access, precise trap entry, MRET, ECALL and EBREAK. All six Zicsr operations apply their read/write suppression rules, including the distinction between selecting x0 and selecting another register that contains zero. The bank defines reset values, access permissions and writable-value constraints, including `mconfigptr` and RV32 `mstatush`. The [CSR execution capture](microcontroller/tests/evidence/csr-control-2026-11-04/README.md) records encoded instruction checks separately from standalone bank verification.

[drg5_irq_platform.sv](microcontroller/rtl/drg5_irq_platform.sv) added retained software and external interrupt events plus timer state. CPU integration preserves pending events while masked, re-evaluates eligibility after relevant CSR writes and MRET, and gives older synchronous faults priority. WFI stops instruction admission without requiring acquisition clocks to stop. The [interrupt execution](microcontroller/tests/evidence/irq-control-2026-11-04/README.md) and [fetch interaction](microcontroller/tests/evidence/irq-fetch-2026-11-04/README.md) captures exercise wakeup, entry boundaries and outstanding-request handling under their declared configurations. Their latency results depend on the tested memory-service bounds and do not establish full-system response with later features.

## 2026-11-01

[drg5_control.sv](microcontroller/rtl/drg5_control.sv) introduced F, D, X, M and W ownership, valid/ready transfers, reset and flush handling, ordered retirement, minimal trap state and a verification trace. [drg5_control_pkg.sv](microcontroller/rtl/drg5_control_pkg.sv) defines the instruction and transaction metadata. A diagnostic configuration permits one instruction in flight while retaining the five-stage structure; overlapping execution uses the same retirement boundary. Exposed memory requests retain their owners through a hart reset until they drain or the platform establishes isolation.

The independently testable datapath added [drg5_decoder.sv](microcontroller/rtl/drg5_decoder.sv), [drg5_immediate.sv](microcontroller/rtl/drg5_immediate.sv), [drg5_alu.sv](microcontroller/rtl/drg5_alu.sv), [drg5_shifter.sv](microcontroller/rtl/drg5_shifter.sv) and [drg5_regfile.sv](microcontroller/rtl/drg5_regfile.sv). These define instruction legality, operand use, arithmetic, shifts and register read/write behavior. The standalone register-file [mapping capture](microcontroller/synth/evidence/register-file-2026-11-04/summary.json) supports distributed RAM with asynchronous reads and write-through forwarding. The controller retains its own integrated register array; x0 is fixed at zero, while other registers have no assumed reset value.

[drg5_fetch.sv](microcontroller/rtl/drg5_fetch.sv), [drg5_fetch_guard.sv](microcontroller/rtl/drg5_fetch_guard.sv) and [drg5_fetch_buffer.sv](microcontroller/rtl/drg5_fetch_buffer.sv) added tagged request ownership, execute-region checks and instruction parcel assembly. The initial fetch path assembled 32-bit instructions while preserving length metadata and buffering for later compressed execution. Redirects discard stale responses and wrong-path faults, and sticky discard prevents an old response becoming valid when a generation counter wraps. Side-effectful peripheral regions are rejected before fetch launch.

[drg5_branch.sv](microcontroller/rtl/drg5_branch.sv) added all conditional branches, JAL and JALR, including signed comparisons, link addresses and configuration-dependent alignment. JALR clears target bit zero. Targets are calculated in X but redirects commit at W, so older faults retain priority and a stalled instruction cannot redirect repeatedly. The [control-flow capture](microcontroller/tests/evidence/control-flow-2026-11-04/README.md) records directed execution and dependency checks.

[drg5_lsu.sv](microcontroller/rtl/drg5_lsu.sv) and the controller's request manager added byte, halfword and word accesses, little-endian byte enables, load extension, alignment and region checks. Loads targeting x0 still perform the access and can fault. One outstanding data transaction and ordered launch prevent younger side effects from escaping an older fault; uncertain completion retains ownership rather than triggering automatic replay. The [memory execution capture](microcontroller/tests/evidence/memory-2026-11-04/README.md) checks architectural results and physical effects independently.

[drg5_forward.sv](microcontroller/rtl/drg5_forward.sv) selects the newest matching older producer for arithmetic, branch, address and store-data operands. An unready match stalls the consumer instead of exposing an older value, and loads become sources only after successful completion. The [base execution capture](microcontroller/tests/evidence/base-2026-11-04/README.md) compares diagnostic, overlapping and forwarded configurations across the base instruction encodings, traps and memory effects. This packet-driven prototype did not yet establish complete RV32I platform qualification.

## 2026-10-30

The CPU specification defined one little-endian, machine-mode hart and separate intermediate feature profiles. It pinned RV32I 2.1, M 2.0, C 2.0, Zicsr 2.0, Zifencei 2.0, Machine Architecture 1.13 and Debug 1.0, with explicit alignment, reset, exception, CSR and unsupported-operation behavior. The current [CPU guide](microcontroller/rtl/README.md) distinguishes configurable core features from the capabilities selected by each platform wrapper.

Platform budgets separated CPU block processing from ADC conversion timing, serial capture, timestamps and raw-data movement. The proposed 256-frame block at 50 kSPS gives a 5.12 ms interval; the initial 80 MHz target reserved 4 ms for firmware and specified memory-service, interrupt, halt, division and resource limits. These were design targets rather than measured performance. Toolchain planning selected Ubuntu/Linux and ULX3S v3.1.7 with an LFE5U-85F-6BG381C, using the open-source synthesis flow now described in the [synthesis guide](microcontroller/synth/README.md). Small-design tool checks did not establish physical programming or integrated CPU timing.

The interface contract established request ownership at first valid, with stable payload through acceptance and retained responsibility through response. Interrupt and debug arbitration precede launch; instruction metadata preserves PC, original bits, length, operands, results and faults across stalls and redirects. The simulation design specified independently delayed acceptance and completion, side-effectful MMIO counters, error responders, reproducible seeds and separate retirement and bus-effect checks. These were specification and test-environment definitions; operational CPU verification followed with the implementations described above.
